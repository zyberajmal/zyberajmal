# KnowBe4 Security Awareness

## Project Overview

This project focused on strengthening the organization’s human security layer through a structured security awareness and phishing-resilience program using KnowBe4.

The environment already used security awareness training through Mimecast, but the existing approach had limitations. The organization needed a more practical way to run phishing exercises, assign training, release security policies, coach users and track awareness activity over time.

KnowBe4 was introduced as the replacement platform after testing phishing exercises and reviewing the need for a stronger awareness program.

This case study is intentionally generalized for public presentation. User names, campaign templates, internal policy documents, phishing statistics, departmental results and organization-specific reporting are excluded.

## Business Context

The organization operated in a marketing-focused environment where employees frequently registered for external services and websites using company email addresses.

This increased exposure to spam, phishing and other unwanted email activity.

Technical email-security controls were important, but they could not eliminate every social-engineering risk. Users still needed to recognize suspicious messages, understand safe behavior and know how to respond when something looked unusual.

The security-awareness program therefore complemented email filtering and other technical controls by focusing on user behavior and security decision making.

## Assessment and Platform Change

The organization initially used Mimecast Awareness Training as part of its security-awareness program.

The existing platform provided a starting point, but limitations were identified as the program developed.

Phishing exercises were tested as part of the evaluation process, and KnowBe4 was then selected and deployed as the replacement platform.

The goal was not simply to change vendors. The objective was to build a more useful awareness process around recurring phishing tests, training, policy acknowledgement, coaching and reporting.

## Program Design

The security-awareness model combined several activities rather than relying on a single annual course.

The program included:

1. Phishing simulations
2. Security awareness training
3. Recurring awareness campaigns
4. Policy publication and acknowledgement
5. Security coaching
6. User education materials
7. Monthly awareness tracking
8. Documentation and follow-up

This created a continuous learning model where users were exposed to practical security scenarios and then supported with training and guidance.

## Phishing Simulations

Controlled phishing simulations were used to help users practice identifying suspicious messages in a safe environment.

The purpose of the exercises was educational rather than punitive.

Phishing simulations helped reveal where users needed more support and provided a practical way to reinforce behaviors such as:

- Checking sender information carefully
- Being cautious with unexpected links
- Questioning unusual requests
- Recognizing urgency and social-engineering techniques
- Avoiding unnecessary credential submission
- Reporting suspicious messages through the appropriate process

The exact campaign templates, simulation frequencies and internal results are intentionally excluded from this public version.

## Security Awareness Training

KnowBe4 was used to assign and manage security-awareness training.

Training topics supported the broader objective of helping users understand common security risks and their role in protecting company information and systems.

The awareness program was reinforced through recurring sessions and tracking rather than relying only on one-time onboarding training.

Monthly awareness activity formed part of the operating model so that security education remained visible throughout the year.

## Policy Publication and Acknowledgement

The platform was also used to publish security policies for user review and acknowledgement.

This connected security awareness with governance because users were not only being trained on threats, but were also expected to understand the organization’s security requirements.

Policy acknowledgement created a clearer record that important security expectations had been communicated to users.

The public case study does not include internal policy names, policy content or acknowledgement records.

## Security Coaching

Not every user responds to security training in the same way.

The program therefore included security coaching as an additional support mechanism.

Where awareness activities showed that a user needed more guidance, coaching could reinforce the specific behavior or security principle involved.

This was important because the objective was to improve user decisions over time rather than simply record whether someone passed or failed a simulation.

## Awareness Campaigns and Materials

Security awareness was also supported through communication outside the training platform.

The broader awareness work included materials such as:

- Security posters
- Newsletters
- Training materials
- Awareness messages
- Policy releases
- Security campaign content

Using multiple communication formats helped keep security visible without relying on users to remember a single annual training session.

The aim was to make secure behavior part of normal workplace awareness.

## Tracking and Continuous Improvement

Awareness activity was tracked over time to understand whether the program was improving user risk posture.

The work included monitoring areas such as:

- Training participation
- Phishing exercise performance
- User risk indicators
- Campaign completion
- Policy acknowledgement
- Areas requiring additional coaching or awareness

The exact internal metrics are not published here.

The documented outcome was a reduction in phishing failure, an improved user risk profile and a significant reduction in the organization’s Phish-Prone Percentage over time.

These results were supported by recurring training, phishing exercises, awareness campaigns and follow-up rather than a single isolated activity.

## Security Reporting Culture

One of the broader benefits of the program was a stronger culture around security reporting.

Awareness training helped reinforce that users should not ignore suspicious activity or assume that reporting a questionable message would create unnecessary work.

A stronger reporting culture improves security operations because users can provide early visibility into phishing attempts and unusual activity that may not yet have been detected through technical controls alone.

The human layer therefore became part of the wider detection and response process.

## Lessons Learned

### Technical controls cannot remove all phishing risk

Email filtering and endpoint security reduce exposure, but users still need to recognize suspicious requests and make safe decisions.

### Awareness works better as a continuous program

Recurring training, simulations and campaigns create more sustained awareness than a single annual training session.

### Phishing simulations should be educational

The objective is to help users recognize real attack patterns and improve their behavior, not to punish mistakes.

### Metrics should guide improvement

Tracking user risk indicators and phishing performance helps identify where additional training or coaching is required.

### Policy acknowledgement connects awareness with governance

Security training becomes more effective when users also understand the organization’s formal security expectations.

### Different users need different levels of support

Some users may need additional coaching after simulations or training. A flexible program can address this without treating every user the same.

### Security communication should use multiple formats

Posters, newsletters, training content and campaign messages reinforce security awareness in different ways and help keep important topics visible.

### Reporting culture matters

Users can provide valuable early warning when they know how and when to report suspicious activity.

### Documentation preserves program knowledge

Campaigns, policies, procedures and lessons should remain documented so the awareness program can be maintained and improved over time.
